# ZDT_EmmV5 库改动记录

> 性质：官方库本身**未改动源码**（遵守"不修改官方 lib"铁律）。
> 本文档记录「以用户手册为准」对通信协议结论的核对结果，以及上层 `Arm.c/Arm.h` 为绕开官方库错位所采取的做法。
> 权威依据：《ZDT_X42S 第二代闭环步进电机用户手册 V1.0.5》（2026-05-27）。

---

## 一、发现的问题：官方库命令码映射错位

官方库 `zdt_emmv5.c` 的 `ZDT_EmmV5_Read_Sys_Params()` 中，`ZDT_SysParams_t` 枚举 → 命令码的映射与手册 §5.5 不一致：

| 枚举名 | 官方库发的命令码 | 手册权威命令码 | 正确含义 |
|--------|:---:|:---:|---|
| `ZDT_PARAM_VER`   | 0x1F | 0x1F | 固件+硬件版本 ✅ |
| `ZDT_PARAM_RL`    | 0x20 | 0x20 | 相电阻/相电感（命名误导，"RL"其实是相电阻电感）|
| `ZDT_PARAM_PID`   | 0x21 | —   | （0x21 手册未明确，官方库自造） |
| `ZDT_PARAM_VBUS`  | 0x24 | 0x24 | 总线电压 ✅ |
| `ZDT_PARAM_CPHA`  | 0x27 | 0x27 | 相电流 ✅ |
| `ZDT_PARAM_ENCL`  | 0x31 | 0x31 | 线性化编码器值 ✅ |
| `ZDT_PARAM_TPOS`  | 0x33 | 0x33 | 目标位置 ✅ |
| `ZDT_PARAM_VEL`   | 0x35 | 0x35 | 实时转速 ✅ |
| `ZDT_PARAM_CPOS`  | **0x37** ❌ | **0x36** | **实时位置（官方库发成了位置误差！）** |
| `ZDT_PARAM_PERR`  | （无映射，枚举里缺）| 0x37 | 位置误差 |
| `ZDT_PARAM_FLAG`  | 0x3A | 0x3A | 状态标志 ✅ |
| `ZDT_PARAM_ORG`   | 0x3B | 0x3B | 回零状态 ✅ |
| `ZDT_PARAM_CONF`  | 0x42 0x6C | 0x42 0x6C | 读驱动配置 ✅ |
| `ZDT_PARAM_STATE` | 0x43 0x7A | 0x43 0x7A | 读系统状态 ✅ |

**核心错误**：`ZDT_PARAM_CPOS`（实时位置）被映射成 `0x37`，而 `0x37` 在手册里是「位置误差」命令；真正的实时位置应是 `0x36`。且官方库枚举缺 `PERR`(0x37) 的独立映射。

> ⚠️ 后果：若上层调 `ZDT_EmmV5_Read_Sys_Params(addr, ZDT_PARAM_CPOS)` 想读实时位置，
> 实际发的是 `0x37`（位置误差），拿到的数值语义完全不对。

---

## 二、采取的应对措施（上层 Arm 层，不动官方库）

为避免踩坑，`Arm.c/Arm.h` **不再走官方库的 `Read_Sys_Params` 枚举**，而是：

1. 在 `Arm.h` 用独立的 `ARM_CMD_*` 常量直接标定命令码（以手册 §5.5 为准）：
   ```c
   #define ARM_CMD_VER   0x1F
   #define ARM_CMD_TPOS  0x33
   #define ARM_CMD_VEL   0x35
   #define ARM_CMD_CPOS  0x36   // 实时位置（修正官方库 0x37 的错位）
   #define ARM_CMD_PERR  0x37   // 位置误差
   #define ARM_CMD_FLAG  0x3A
   #define ARM_CMD_ENCL  0x31
   ```
2. 在 `Arm.c` 新增**手动组帧 + 帧锁存解析**接口，彻底绕开官方库错误映射：
   - `Arm_ReadVersion()`：解析固件/硬件版本（§5.5.2）
   - `Arm_ReadValue()`：读「符号+数值」型（位置/误差/转速，§5.5.11/13/14）
   - `Arm_ReadFlags()`：读状态标志（§5.5.15）
   - `Arm_ValueToInt32()`、`Arm_RawToDeg()`：符号/量纲转换辅助

## 三、协议要点（以手册核对，关键量纲）

### 版本 §5.5.2
```
主机发：Addr 1F 6B
电机返：Addr 1F FW_Ver(2B大端) HW_Series HW_Type HW_Ver 6B
```
- `FW_Ver`：16 位，200=V2.0.0。
- `HW_Series`(bit15-12)：0=X 系 / 1=Y 系。
- `HW_Type`(bit11-8)：2/3/4/5/6=28/35/42/57/86。
- `HW_Ver`(bit7-0)：14=V2.0。

**⚠️ 实机回包为 7 字节，非手册 8 字节**：
```
实机：01 1F 00 CC 23 14 6B   (7B)
      ▲ ▲  └FW_Ver=0x00CC=204(V2.04)
      ▲ ▲        └HW_Ser=0x23  HW_Type=0x14
      ▲ 1F                    └缺独立 HW_Ver，直接 6B
```
- `Arm_ReadVersion()` 已写成 **兼容 7~8 字节**：`FW_Ver=frame[2..3]`，`HW_Ser=frame[4]`，`HW_Type=frame[5]`，若 8 字节则 `HW_Ver=frame[6]`。

### 实时位置 §5.5.13
```
主机发：Addr 36 6B
电机返：Addr 36 符号(00/01) 位置(4B 00000000-FFFFFFFF) 6B   (8B)
Emm 量纲：0-65535=一圈 360°，角度 = 值 × 360 / 65536
```

### 位置误差 §5.5.14
```
主机发：Addr 37 6B
电机返：Addr 37 符号(00/01) 误差(4B) 6B   (8B)
Emm 量纲：角度 = 值 × 360 / 65536
```

### 实时转速 §5.5.11
```
主机发：Addr 35 6B
电机返：Addr 35 符号(00/01) 转速(2B 0000-1388) 6B   (6B)
Emm 量纲：RPM（X 固件才是 0.1RPM，需 /10）
```

### 状态标志 §5.5.15
```
主机发：Addr 3A 6B
电机返：Addr 3A 标志(1B) 6B   (5B)
bit0 Ens_TF使能 | bit1 Prf_TF到位 | bit2 Cgi_TF堵转 |
bit3 Cgp_TF堵转保护 | bit4 Esi_LF左限位 | bit5 Esi_RF右限位 | bit7 Oac_TF掉电
```

## 五、遗留 / 待办

- 实机回包「版本 7B vs 手册 8B」差异待更多板子验证（可能不同批固件有别），`Arm_ReadVersion` 已做兼容。
- 后续写「机械臂步进电机控制文档」时，直接引用本记录的 ARM_CMD_* 量纲，勿再用官方库枚举。

## 六、追加：按键触发 + 解析显示（2026-10-01 下午）

- 把 `main.c` 从「每 2s 自动发版本」改为「矩阵按键触发读参数 + 解析显示」。
- 按键 → 命令 → OLED 显示：
  | 键 | 命令 | 命令码 | OLED 显示 |
  |---|---|---|---|
  | 键 1 | 读版本 | 0x1F | FW 版本 + HW_Ser/HW_Type |
  | 键 2 | 读实时位置 | 0x36 | 带符号位置值 |
  | 键 3 | 读位置误差 | 0x37 | 带符号误差值 |
  | 键 7 | 读状态标志 | 0x3A | Flag 字节 + ens/rch 位 |
  | 键 9 | 读实时转速 | 0x35 | 带符号 RPM |
- `Arm.c` 新增 `static void Arm_SendReadCmd(cmd)` 辅助：组 `[addr][cmd][0x6B]` 三字节发送，三个解析函数（Version/Value/Flags）内部自发改命令再收帧，main 层无需手动组帧。
- 发光点：解析函数**阻塞等待一帧**（在 MainTask 5ms 循环里一次性完成收发），超时 ARM_TIMEOUT_MS 200ms。
